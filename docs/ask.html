How this works, limits and sources

Search. A BM25 ranking over every article of the loaded instruments, split into passages. It runs entirely in your browser on the verbatim text in the law reader. Common abbreviations (PEP, STR, CDD, DORA terms) are expanded and shown to you. An article reference such as "Article 19 AMLR" is matched exactly.

Answer. If you add your own key, the question and the retrieved passages are sent from your browser straight to the model provider, with a prompt that restricts the model to the numbered sources. RegRadar has no server in this path.

Check. Every quotation mark in the answer is tested as a verbatim substring (ignoring case, whitespace, quote and hyphen style) of the passage it cites. This catches altered or invented quotes. It does not check whether the reasoning is right, whether the retrieved passages are the right ones, or whether the law has been amended since the parsed text.

Limits. English texts only. Only the instruments parsed in RegRadar are searched; national transposition, delegated acts, technical standards and guidance are not included. Retrieval can miss the relevant article: if the question is important, read the article and its neighbours in the law reader.

Provider documentation used for the Anthropic call:

    The browser-access header name is confirmed in the SDK source linked above; the API docs describe the SDK's browser mode as opt-in and warn about key exposure. The second provider option (any OpenAI-compatible endpoint with a base URL you supply) follows the common chat-completions format, was cross-checked against third-party documentation only, and is experimental. The live model call has not been tested end to end by RegRadar; the request, streaming and error handling are tested against mocked responses.
